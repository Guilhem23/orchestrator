# Composition Security Remediation and Test Provenance Model

## 1. Overview and Threat Model

The Slice Orchestrator control plane enforces deterministic state transitions, scope manifest boundaries, and signed evidence receipts. However, independent security review identified a composition-level vulnerability:

> An agent controlling candidate code and tests could modify or remove authoritative test cases, run tests against the modified test suite, obtain a genuine HMAC-signed passing receipt, self-approve as an adversarial reviewer, and pass the commit gate with a safety regression intact.

To resolve this vulnerability, we establish an explicit **Test Provenance Model** and **Composition Security Controls** that prevent candidate changes from self-authorizing or redefining security-critical tests.

## 2. Test Provenance Taxonomy

Tests are classified into three distinct provenance levels:

### 2.1 AUTHORITATIVE_CONTROL_TEST
* **Definition**: A safety-critical test defined in a trusted baseline revision (`base_commit_oid`) prior to candidate implementation.
* **Trust Level**: Trusted control-plane evidence.
* **Immutability**: Immutable for the duration of the candidate run.
* **Modification Policy**: A worker cannot delete, weaken, or modify an authoritative control test. Any candidate diff that modifies or deletes an authoritative control test without explicit independent human or controller re-approval causes immediate commit-gate rejection (`AUTHORITATIVE_TEST_DELETED` or `AUTHORITATIVE_TEST_MODIFIED`).
* **Gate Requirement**: Mandatory for commit authorization.

### 2.2 CANDIDATE_TEST
* **Definition**: A new or modified test introduced by the worker during implementation or remediation.
* **Trust Level**: Secondary evidence.
* **Modification Policy**: Workers may add candidate tests to cover new features or bug fixes.
* **Gate Requirement**: Candidate tests provide supplementary evidence but cannot replace missing or failing authoritative control tests. Adding candidate tests alone cannot establish safety if authoritative tests fail or are deleted.

### 2.3 EXTERNAL_TEST
* **Definition**: A test executed outside the candidate tree or from a separate trusted checkout.
* **Trust Level**: Fully isolated external authority.
* **Gate Requirement**: Used for out-of-tree security or integration validation where applicable.

## 3. Persisted Test Provenance Metadata

For every control test set, the control store persists:

| Field | Type | Description |
|---|---|---|
| `test_id` | String | Unique identifier for the test definition |
| `source_location` | String | Repository-relative path to the test file |
| `trusted_baseline_revision` | String | Git commit OID (`base_commit_oid`) where the test was established |
| `content_digest` | String | SHA-256 digest of the test file content at baseline |
| `command` | String / Array | Resolved test command execution vector |
| `expected_behavior` | Dict | Expected exit code (0) and pass criteria |
| `authorizing_principal` | String | Principal that established or approved the test baseline |
| `creation_timestamp` | String | ISO-8601 timestamp of baseline record |
| `scope` | Array | Scope/target files covered by the test |
| `immutable` | Boolean | `True` for authoritative control tests |

From this metadata, the control plane derives a canonical `trusted_test_set_digest`:

$$\text{trusted\_test\_set\_digest} = \text{SHA256}(\text{canonical\_json}(\text{authoritative\_test\_manifest}))$$

## 4. Test Authority Enforcement Mechanisms

To guarantee test authority:

1. **Baseline Snapshotting**: Upon slice run opening or plan approval, the control plane captures the tree OID and computes the `trusted_test_set_digest` for all authoritative test files in `base_commit_oid`.
2. **Deletion & Modification Guard**: `GateEvaluator` verifies that every authoritative test file present at baseline exists in the candidate tree with an unmodified content digest (unless an explicit re-approval event exists).
3. **Receipt Binding**: HMAC-signed test receipts generated by `slice_run_tests` / `run_control_test` bind:
   - `slice` and `run_id`
   - `candidate_tree_oid`
   - `workspace_revision_digest`
   - `trusted_test_set_digest`
4. **Commit Gate Verification**: `evaluate_commit_gate` requires a passing test receipt whose `trusted_test_set_digest` matches the baseline test set, ensuring test-set immutability.
5. **Fail-Closed Command Execution**:
   - Empty commands are rejected (`EMPTY_TEST_COMMAND`).
   - Missing test commands or missing test files fail closed.
   - Non-zero expected exit codes are rejected (`EXPECTED_EXIT_CODE_ABUSE`).
